# 要件定義書 — LiveDesign

## 1. 背景と課題

TikTok LIVE などのライブ配信では、ギフト・コメント・フォローに合わせて**画面上で演出を出す**ことが視聴者との交流の中心になっています。しかし既存のツールには、

- デザインツール（Canva・Photoshop）と、イベント連動ツール（TikFinity など）が別々で、行き来が多い
- 「ギフトでボールが降るゲーム」のような**オリジナルの演出を作るにはプログラミングが必要**
- 配信者ごとにローカルで動かすツールが多く、PC を変えると設定を持ち運べない

という課題がありました。

## 2. 目的

**配信画面のデザインから、イベントで動く演出・ミニゲームづくりまでを、ブラウザだけで完結させる Web サービス**を提供する。

| モード | 目的 |
|---|---|
| アーティストモード | Canva のような操作で配信画面をデザインし、「ギフト 100 コイン以上で紙吹雪」をノーコードで組み立てる |
| クリエイターモード | Unity / Unreal Engine のような画面で、ノードをつなぐだけでゲームや演出（ギミック）を作る |

## 3. 対象ユーザー

| ペルソナ | 特徴 |
|---|---|
| TikTok LIVE の配信者 | 配信画面を自分らしく飾りたい。ギフトをくれた人に演出で応えたい |
| ゲーム実況者 | OBS を使っている。延長タイマーやゴールゲージを手軽に置きたい |
| 演出を作りたい人 | プログラミングはできないが、視聴者参加型のゲームを作りたい |
| 運営者 | サービスを VPS 1 台で安く運用したい |

## 4. 機能要件

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | 会員登録・ログイン | メール＋パスワード、Google、TikTok |
| F-02 | TikTok 接続 | @ID を入れるだけ（パスワード不要）。配信が始まるまで待って自動で接続 |
| F-03 | デザイン | 図形・ペン（ベジェ）・鉛筆・文字（Google Fonts 30 種）・画像・動画、グラデーション・効果・描画モード・アニメーション、レイヤー・グループ、Undo/Redo |
| F-04 | 配信ウィジェット | チャット・弾幕・アラート・ゴール・ランキング・最近のイベント・タイマー・ギミック |
| F-05 | 値の差し込み | `{likes}` `{lastGifter}` `{top1Name}` やカウンター・タイマーの値を文字に差し込む |
| F-06 | ルール（イベント → アクション） | 8 種のきっかけ × 条件 × クールダウン × 10 種のアクション |
| F-07 | テスト | エディタからコメント・ギフト・フォローを流して確認 |
| F-08 | オーバーレイ | OBS / TikTok LIVE Studio に URL を貼るだけ。保存するとその場で反映 |
| F-09 | ギミックの作成 | オブジェクト・プレハブ・物理・当たり判定・パーティクル・効果音シンセ |
| F-10 | ブループリント | ノードと線でプログラミング。イベント・フロー・計算・変数・オブジェクト操作 |
| F-11 | 関数・マクロ | 自作ノード。ピュア関数、出口が複数のマクロ、選択ノードからの関数化 |
| F-12 | テンプレート・ミニゲーム | デザイン 6 種、ギミック 7 種、ミニゲーム 6 ジャンル |
| F-13 | 素材 | 画像・動画・音のアップロード（容量制限つき） |
| F-14 | 書き出し・読み込み | デザインとギミックを JSON で |
| F-15 | 外部連携 | API キーでイベント投入・カウンター操作 |
| F-16 | アカウント設定 | 合鍵・API キーの作り直し、パスワード変更、アカウント削除 |
| F-17 | 運営 | 利用者一覧・プラン変更・パスワード再設定（CLI）、新規登録の停止、利用者ごとの上限 |

## 5. 非機能要件

| 区分 | 要件 | 実現方法 |
|---|---|---|
| セキュリティ | 他人のデータに触れない | すべての REST・WebSocket・素材を本人のものに限定。他人の ID を指定しても 404 |
| セキュリティ | Web の代表的な攻撃に耐える | CSRF（Origin 検査）・XSS（CSP・文字としての描画）・総当たり（回数制限）・オープンリダイレクト対策 |
| セキュリティ | 人からもらった JSON で乗っ取られない | ノードと式を自前の手順で解釈し、`eval` を使わない |
| 可用性 | 作りの悪いギミックで配信を止めない | 無限ループ・再帰・オブジェクト数を上限で止め、コンソールに理由を出す |
| 可用性 | 再起動しても画面が戻る | 画面は自動で WebSocket を繋ぎ直す。停止時にカウンターを書き出す |
| 性能 | 同じ @ID への接続を増やさない | @ID ごとに 1 本を共有 |
| 性能 | メモリを無駄に使わない | 使っている人の作業場だけをメモリに置く |
| 運用 | 安く始められる | Node 標準の SQLite、Docker 1 コンテナ、メモリ 1GB から |
| 保守性 | 構造の決まりを壊さない | 依存の向き・公開範囲・ログインの付け忘れをテストで検出 |
| 保守性 | 品質を自動で確かめる | 自己テスト 687 件（本物のサーバーを空きポートで立てる結合テストを含む） |

## 6. 公開前に決めること（未実装）

| 項目 | 理由・方針 |
|---|---|
| 利用規約・プライバシーポリシー | TikTok Login Kit の審査でも必要 |
| パスワード再設定メール | メール送信サービスが必要。現状は Google / TikTok ログインか運営の CLI で対応 |
| 有料プラン | `users.plan` を使って Stripe などで追加 |
| TikTok 非公式ライブラリへの依存 | `tiktok-live-connector` は非公式。TikTok 側の変更や利用規約との関係を理解したうえで公開する |
