# テスト仕様・結果 — LiveDesign

## 1. 方針

| 種類 | ねらい |
|---|---|
| 構造テスト | フォルダ構成・公開範囲・依存の向き・ログインの付け忘れなど、**設計の決まり**そのものをコードから機械的に検査する |
| ロジックテスト | `lib/` と `shared/gimmick/` の純粋ロジック（パスワード・ルール判定・式・ブループリントの実行・ミニゲーム）を単体で検証する |
| フローテスト | **本物のサーバーを空きポートで立てて** HTTP / WebSocket を通し、登録から配信イベントの到達、利用者ごとの分離までを確認する |

外部ライブラリのテストフレームワークは使わず、`test/run.mjs` が `test/*.test.mjs` を 1 本ずつ別プロセスで実行します（`npm test -- auth` で名前を絞り込み可能）。TikTok との接続は偽の接続（`setConnectionFactory`）に差し替えて検証しています。

## 2. 実行方法

```bash
npm install
npm test
```

プッシュごとに GitHub Actions（`.github/workflows/test.yml`）でも同じテストを実行しています。

### 代表的なテストケース（抜粋）

| No | ケース | 期待結果 |
|---|---|---|
| 1 | ログインしていない状態で大きな本文を PUT | 本文を読む前に 401 |
| 2 | 別の利用者のデザイン ID を指定して取得・更新 | 404（存在を明かさない） |
| 3 | Origin が他サイトの書き込み | 403 |
| 4 | API キーでデザインを読み書き | 401（使えるのはイベントとカウンターだけ） |
| 5 | 合鍵を作り直す | 古い URL の OBS が切断される |
| 6 | 2 人が同じ @ID を入れる | TikTok への接続は 1 本、イベントは両方に届く |
| 7 | 全角の `！ｊｕｍｐ` とコメント | `!jump` のルールが発火する。`!jumpman` には反応しない |
| 8 | いいねが塊で届き、ルールの「N 件ごと」の区切りを 2 回跨いだ | 跨いだ回数ぶん（2 回）発火する |
| 9 | 式に `constructor` や関数呼び出しを書く | 実行されず、エラーとしてコンソールに出る |
| 10 | 実行の線がぐるぐる回る・合図が合図を呼び続けるブループリント | 打ち切られ、理由がコンソールに出る（「待つ」をはさんだ連鎖は止めない） |
| 11 | 「ミニモンスター」で !たたかう → !ボール | 弱らせてつかまえ、図鑑に登録される |
| 12 | デザインに `__proto__` キーを含む JSON | 無視され、プロトタイプ汚染が起きない |
